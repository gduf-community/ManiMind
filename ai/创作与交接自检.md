# 创作与交接自检

面向后续各题材的制作引导，来自本轮真实返修。与所选 native stage 契约一起使用；旧批准、profile 和原生来源保持原样。

## 先分清画面中各量的角色

- 当前值、固定基点、历史状态、待计算量和已就绪结果要能辨认。同一位置更新数值时，先核对旧层的去向。
- 分层展示组合函数时，明确哪一层已经更新。需要保留旧输出作比较，就给出清楚状态；计算的展示顺序表达推理，不暗示数学函数存在物理延迟。
- 新条件或新尺寸进入画面前，先处理旧结果的适用范围，再建立新的计算关系。
- 条件变化或调参的前、中、后，把屏幕上的数字、公式条件、尺寸和实际图形分别与科学模型对照。终态正确仍需核对过程中的对象与范围。

这些建议服务于理解与取舍，不规定统一字数、行数、秒数、动作总量或逐字符动画。

## 作者交接前

1. 实看自己将交接的那一版，记录源码、媒体、plan、取证包和自检对应关系。
2. 已知阻断写入新的撤回记录，明确替代哪次旧交接。协调者据此停止旧版本验收；原包、诊断与已完成的独立结论保留。
3. 新候选重新取证后再送审。已有 packets 只表明曾经准备过，不自动代表最后自检之后仍 ready。

## 报告先过自身 schema

- 使用所选 native stage 的准确名称，填写实际独立 Reviewer 的 Agent/context ID，不用显示昵称、角色标签或作者身份替代。
- 过程的主 before、during、after 各保留一个明确定位；额外过程观察放到契约允许的独立字段。先核字段与数据类型，再交给门禁。
- 格式需要修正时，由原 Reviewer 另立版本，保留其实际观察和旧报告；格式修正与内容重新判断分别记录。

## 区分观看覆盖与已观察缺陷

采样帧、时间戳核对和真实 1x 连续观看分别记录范围。缺少连续观看时，标记待补的覆盖与审阅，不直接推断影片有缺陷，也不据此要求重新渲染。

已经实际看见的拥挤、错指、条件残留或数字与图形不符，按具体时刻和影响照实阻断。补审沿已有确定媒体继续；需要改画面时再建立新版本。

本页由项目维护者维护，作者、协调者和独立审核者共同消费；用于后续交接，随实际工作流和 native schema 演进核对。
