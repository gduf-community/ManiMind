# ManiMind 强前置条件约束

## 一、项目级红线

1. 不在当前仓库重复实现 `resources/skills/html-animation/`、`resources/references/hyperframes/`、`resources/skills/manim/SKILL.md` 已经提供的底层能力。
2. 不把长期上下文和短期上下文写进同一份文件或同一路径。
3. 不允许跳过审核 Agent 直接合成最终视频。
4. 不允许用隐式全局状态驱动多 Agent 协作。
5. 不允许把数学事实、论文结论、公式解释只保存在自然语言对话里而不落成结构化摘要。
6. 任何涉及模块边界、角色分布、状态存储路径、上下文装配链路或第三方能力接入方式的结构变更，必须同步更新 `docs/architecture.canvas` 与 `docs/通用项目架构模板.md`。

## 二、架构约束

1. 主 Agent 负责全局状态，不负责直接产出全部媒体细节。
2. 二级协调 Agent 负责任务切分和工具选择，不负责最终审核。
3. 新课程以 Canvas 为主舞台（2026-11-28 用户决定）：画面写成 `seek(t)` 纯函数场景，用 `src/manimind/canvas/` 组装，由固定版本的 HyperFrames 渲染，配音按恒定增益规则另行混入，见[Canvas 主舞台](../../docs/canvas.md)。ManimGL 退为素材源，负责 3D、路径级形变/笔画描出和 KaTeX 不支持的 LaTeX，以透明通道片段并入 Canvas 场景；已发布和冻结的 ManimGL 课程保持原监督入口与独立审核链，不回改。Canvas 成片同样必须经独立审核后才能发布；监督入口接入 Canvas 之前，Canvas 成片只作样片，不进入发布。历史 `plan` CLI 中的 HTML/Manim/SVG worker 保持原输入输出协议，边界见[历史 CLI 隔离](../legacy-cli.md)。
4. 审核 Agent 必须只消费结构化产物和可追溯上下文，不能依赖“记忆里大概看过”。
5. 后处理阶段只能在审核通过后启动。

## 三、上下文约束

### 长期上下文

- 面向项目生命周期保存。
- 保存来源与科学事实摘要（课程教研、科学条件等）、术语表、公式清单、叙事主线、风格规范、审核结论。
- 写入路径固定在 `runtime/projects/<project_id>/`。

### 短期上下文

- 面向单次协作或单个镜头任务保存。
- 保存临时镜头草案、子 Agent 回传说明、局部失败原因、重试痕迹。
- 写入路径固定在 `runtime/sessions/<session_id>/`。

## 四、实现约束

1. 核心编排逻辑优先使用标准库和可验证的纯数据模型。
2. 在 Python 未安装前，可以先完成 PowerShell 初始化与环境检测脚本，但不能伪装成可运行的完整渲染流水线。
3. 所有环境依赖必须显式检测：`python`、`ffmpeg`、`manimgl`、`xelatex`、`dvisvgm`、`node`、`bun`；兼容后端启用时另行检测 `manim`。
4. 所有输出目录都要可预测，不能在随机临时路径下落盘。
5. 所有任务切分规则都要能从配置或代码中追溯。

## 五、外部依赖接入约束

### `resources/skills/html-animation`

- 作为 HTML 科普动画模板来源与提示词能力来源。
- 当前仓库只记录如何调用，不复制其模板内容到自有目录。

### `resources/references/hyperframes`

- 作为 HTML 预览、校验、渲染引擎来源。
- 当前仓库不在根项目内重写 HTML 渲染、帧适配、视频编码能力。
- Canvas 主舞台通过 `tools/hyperframes/` 锁定的 npm 版本调用 `lint`/`render`；仓库只提供把 `seek(t)` 挂到 HyperFrames GSAP 时间轴上的一个时钟适配器，以及 HyperFrames 不具备的数学画面与公式变形动效库。每次调用用 HyperFrames 自己的环境变量关闭遥测、更新检查和自动安装，并锁定浏览器路径，从尝试目录启动以免读取仓库 `.env`。HyperFrames 自带的混音会额外加增益导致削波，所以画面静音渲染，配音由 `canvas/voice.py` 按恒定增益规则混入并无损封装。

### `resources/skills/manim/SKILL.md`

- 作为 ManimCE 能力说明来源，不作为当前默认 ManimGL API 契约。
- 当前仓库负责调用契约与输入输出组织，不重写 Skill 文档中的底层流程。

## 六、交付约束

当前课程交付以[作品命名与交付](../../docs/命名与交付.md)和各阶段原生收据为准，至少包含：

- 通过独立审核的播放包（MP4、`目录.md`、`manifest.json`、制作资料）及原生 delivery 收据
- 正式讲稿与逐课来源（provenance）
- 各阶段独立审核报告（`runtime/sessions/`）
- 版本化源码快照与输出资产清单（`outputs/<project_id>/`）

论文总结、分镜清单、任务分发表、HTML/Manim 片段清单只属于历史 `plan` CLI 流程，见[历史 CLI 隔离](../legacy-cli.md)。
