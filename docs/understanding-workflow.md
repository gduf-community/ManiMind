2026-10-27新增版本。新项目使用`configs/visual-first-workflow-v2.json`，历史v1、114秒成片、旧17句配音器及隔离模型实验保留，不原地改写。这里的变化不是新增统一教学模板，而是把“观众为何能理解”的问题落实为实际审核。

## 创作引导与审核规则

| 方面 | 创作引导，可自主取舍 | 审核标准，必须给当前像素证据 |
| --- | --- | --- |
| 理解目标 | 考虑受众先修、易错直觉和看完能解释什么；不必重推所有基础 | 不能用审核者自己的知识补上影片缺失的关键理由 |
| 可见推理 | 可选对照、过程、变形、反例或其他表示 | 结论有可见依据；模拟、演绎、测量、类比的证据地位不能混淆 |
| 注意力 | 自由布局、配色、静止/运动、局部放大，辅助UI按需出现 | 当前关键关系清晰可读，不被常驻元素、缩小或抢先出现的新推导干扰 |
| 节奏 | 给辨认与思考分配时间，重复可承担新观察任务 | 不以动作量、公式数或片长评分；关键过程不能只在很短窗口内闪过 |
| 语义同步 | 先审视觉，再写稿；保留音色不等于冻结旧录音 | 不只检查句子起点在事件后，还检查整句所指证据持续可读 |
| 术语准确 | 表达可以自然，但使用学科通行的物理量名称，并明确方向、分量、参考点与比较条件 | 画面、旁白与字幕一致；不能把水平速度简写成“横速”，也不能把竖直初速度为零说成初速度为零 |
| 迁移支持 | 可选新例预测、反例或其他收束，不强制每片出题 | 给出的理由能否支持同机制的新问题；编辑判断不能冒充学生实验 |

不新增“必须几幕、每镜几秒、必须有角色、必须反转、必须开方动效、必须测某个固定例子”等生产限制。审核者不得把个人分镜偏好写成通用阻断规则。

### 把解释用在难点

新项目可选`configs/visual-first-workflow-v3.1.json`，沿用v3审核数据结构，将下列引导实际放进作者配置与审核检查；旧v3与既有作品的冻结批准不变。它不新增固定分镜或时长限制。

篇幅和动画精力按观众的想象难度、误解风险与推理缺口分配，不平均分给每个步骤。已能直接看出的线性比例、乘以一、显然的数值比较，可以合并呈现；条件、单位和有效推理仍应可追踪。难以直觉想象的非线性变化，应让观众看到同一时间驱动下的运动、采样间隔、量的增长或几何累积，并把观测变化与公式连接起来，不只增加读数和结论文字。

保留清单保护教学功能，不保护每个曾经使用过的动作。不得自动把搬移标尺、重复描边等表现手段升级为所有后续版本的强前置条件。用户明确要求删去低价值重复时，记录授权及留下的推理链，重新冻结当前合同；不能为了通过旧清单又把该动作加回来。必要的代数中间式可以保持完整，同时更快、并行或紧凑地呈现简单部分。

### 让画面直接说明

观众文案面向知识本身，不为生成过程或含混的画面作辩护。不用“仅用于位置分解”“不是实际运动”“只是示意”“仅供参考”等免责句替代清楚的表达；容易误导的展开、坐标和运动方式，应从画面中改正。科学前提仍须准确、自然地给出，例如忽略空气阻力、重力加速度取值和初始条件；正常的概念辨析、反例也不应被一律禁掉。

制作与审核日志中的来源、失败、听审或测试状态继续如实记录，但不搬进教学画面充当旁白、字幕或常驻提示。

2026-10-29的课程语言返修进一步检查整节叙述：讲对象怎样变化、关系怎样建立、结论从哪里来。连续的“不是某物”“不代表某事”即使逐句正确，也可能挤占这些解释；按整段意义重写，保留有作用的比较和科学条件。连续意群入口的v4.2配置同时引导用通俗、准确的口语解释，必要术语联系具体对象，整节按说话方式通读；详见[课程单元工作流](course-unit-workflow.md#通俗的口语)，本轮状态见[正向讲解返修记录](wave-positive-20261029.md)。旧片的冻结配置和批准继续保留。

字幕是否提供应跟随当前任务，不得把“避免重复字幕”误作默认取消字幕。用户要求字幕时，提供一套可直接观看的字幕，并实际检查与坐标、公式、参数、底部标注的间距。烧录字幕版不同时附带自动加载的同名外挂字幕或默认开启的内嵌字幕轨。字幕逐字对应实际批准讲稿和完整新声；只改字幕、不改含错误术语的旁白或画面，不算术语修正完成。句内拆分若只按字数近似计时，明确不是词级听审/语音识别对齐。

## 实际接入

- `experiments/sol_understanding_first.py`是新Sol自主入口，继承已有自由创作工具。`actor_context`仍加载当前profile；`reviewer_request`实际注入编辑检查，`approval`再次验证，不能只在文档写标准而继续走旧批准路径。
- `review/understanding_quality.py`复用既有六维量表，增加五项真实时点的编辑证据。整片pass仍须至少80/100、四个关键维度至少3，且无blocker、明确授权发布。未听审、未学生测试分别声明。
- `review/semantic_focus.py`不包含课程内容，接收实测可读时间窗与实际WAV长度；整句越界直接拒绝，不自动剪字、加速或拉伸物理时钟。
- `experiments/understanding_support.py`仅在原ManimGL运行时增加`focus_begin/end`，记录实际时刻，不自动替作者判断画面清楚，也不增加可见UI。其他渲染后端可提供等价的可追溯实测数据。
- `postproduce/understanding_render.py`保留每轮源码、profile、实际媒体、事件/焦点及真实抽帧。失败与旧版本不覆盖。
- `postproduce/understanding_film.py`分离静音首看、后写讲稿、声音生成、全句时序和封装的批准；缺少任何当前阶段的独立审核不能发布。
- `postproduce/flexible_voxcpm.py`仅为本轮已选合成V01声线扩展任意句数，复用官方VoxCPM2和冻结helper。它不是通用声音许可工具，不改变旧17句实验。Windows/GPU实测与真实听审另行记录。

模型自主入口（不自动启动、不代表已完成新模型对比）：

```bash

  --config configs/sol61-understanding-first-20261027.json
```

入口边界需分清：新Sol自主适配器当前沿用v1的`VisualLessonScene`、视觉事件和静音/文本交付，确实新增编辑请求及批准检查，但没有自动接入本轮`UnderstandingScene`的focus文件或Windows声音任务。下列监督式入口实际验证了focus、可变句数及分阶段交付；不能把两者并列说明误读为已打通“一条自主命令生成最终配音片”。后续模型接入仍需适配其真实产物并做端到端回归，不能把未运行的新配置算成成功案例。

监督样片渲染入口执行本机受信任的Python源码，不是对抗性沙箱；不能把未经检查的外部候选直接当作安全代码运行。自主模型入口继续沿用冻结执行器已有的源码检查和渲染边界。新增的审核/区间校验不提供代码安全证明。

## 版本与阶段

1. 规划受众、科学边界和理解目标，自主制作静音画面。
2. 真实渲染记录视觉事件和可读区间；独立新上下文先看公共目标与像素，不读作者讲稿/源码/意图。
3. 视觉通过后安装当前后配音稿，另一新上下文核对源码、科学模型、实测区间与稿件。草稿可提前保留意图，但不提前获得正式批准。
4. 用用户选定的本地声音生成每句完整首条，记录实际时长、原音和来源，不隐藏失败或自动重试。
5. 全句排程必须落在对应可读区间内。超出时修改文本或局部视觉，再重新审核受影响阶段；不为了保持旧片长硬塞新内容。
6. 当前真实音画关系独立审核后才混音封装。技术通过、编辑通过、真实听审、学生理解分别记录。

视觉变化使视觉证据、焦点区间和下游文字/声音绑定失效，必须重渲染；只改讲稿不要求重渲染未变画面，但需要新讲稿审核/声音。修改发布器或审核契约需要新批准，不重新标记旧报告为有效。

## 不过拟合的验证

### 公式节奏与自然旁白

辨认、变化、落定是不同的观看任务。作者应给初态和新符号留出辨认时间，每次只推进一个能说清的代数操作；移动结束后保留可读状态，再开始下一步。不能仅延长结尾静帧、统一降低全片播放速度，或加速旁白来掩盖中间推导过密。物理演示的模型时钟与讲解的呈现时长分开。

审核者应检查连续代入、消零、移项、约分、开根及最终合并的实际前中后画面，不以平均镜头长度或公式终态存在作为节奏通过证据。字幕、说明和变量同时变化时，还要检查观众是否必须在多个位置间来回抢读。具体秒数由当前受众、符号复杂度及真实语音决定，不写成通用固定模板。

声音在视觉批准后生成。逐句保留原速完整首条，检查真实时长能否覆盖其对应可读窗口；容不下时返工局部视觉或经重新审核的文字，不能剪掉句尾或偷偷变速。时序与解码通过不等于发音、自然度或学生理解通过。

本轮将调度与审核契约用于不同题材的结构化测试，并保留“起点满足但整句越界”“预测问题讲到答案已出现”“工程pass但机制有缺口”等反例。它们验证软件契约，不等于已验证其他学科成片质量。进一步验证创作泛化应选择没有用于制定本轮规则的新题做留出制作；不能把示例片的具体布局、时间、数值或修法加到通用profile里。

`tests/fixtures/projectile-understanding/`保存示例的只读干跑测试样本，不是项目当前状态或审核证据，测试收集不依赖本机被忽略的runtime产物。声音单测用人工PCM和替身验证拒绝路径；已有本机V01/模型收据的哈希核对是可选附加检查，缺少这些私有媒体不阻断干净checkout的离线测试。

声音来源校验从已批准交付重建视频及focus路径，并核对实际哈希，不接受计划自报的替代窗口。逐句回执、计划、文本、参考声音、worker/helper身份、完整48kHz PCM和削波在排程及最终发布前重复核验；同长度或自洽的新文件哈希不能代替来源对应。这些是工程拒绝条件，仍不等于能从哈希判断发音自然或真正讲出了指定文字。
