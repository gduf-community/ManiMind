# 优化时保留有效细节

2026-10-27新增。起因是147秒理解优先样片虽然通过独立首看，却省掉114秒旧版的多组完整推导。新版单独可懂，不等于旧版有效内容没有退步。此规则保护解释功能，不保护所有旧画面或装饰，也不规定通用分镜模板。

## 制作引导

1. **先选基线，再改作品。** 按当前任务记录旧版已经有效的推理步骤、变量身份、图形与公式联系、单位、条件及有意义的运动。新主题从零制作可声明`fresh`，不是每部视频都需要模仿旧片。
2. **减少同屏负担，不减少解释层次。** 可用逐步显现、连续对象、焦点变化、局部放大、重排或调整时长；不能把有用的中间理由直接换成结论，再把空出的时间用于等待。
3. **每项变化有去向。** 可以保留、用功能等价的表达替换，或明确报告丢失。等价替换需说明观众仍能得到什么理由，不要求像素、布局、镜头数或符号位置不变。
4. **有取舍，不暗删。** 本轮任务明确要求保留的项不能由作者用“更简洁”自行取消。确需改变范围，先取得任务授权，再新建合同版本；不能修改原合同来让已经失败的比较变成通过。
5. **不按数量奖励细节。** 装饰、无任务重复、重复标题和无关参数不因旧版存在就自动受保护。基线清单必须写清教学功能；新增动作、公式、片长或字幕不能抵消关键理由缺失。

## 独立审核

- **新版首看**：独立新上下文只看当前公共目标和实际像素，判断单独是否成立。不用旧版或作者意图替新版补理由。
- **内容回归**：另一独立上下文看任务选定的基线及新版真实画面，逐项核对。变量移动、代入、对照等过程必须有前、中、后三阶段像素证据，不能凭最终公式还在就通过。
- **文字与声音**：内容回归和视觉首看都通过后，才安装正式后写讲稿。讲稿另审；真实声音生成后仍做完整句时序和听感验收，不复用旧声音批准。

审核结果`retained`表示功能保留，`equivalent`表示功能等价并需理由，`lost`表示丢失。当前合同选定的任一细节为`lost`、缺项或缺实际证据时，发布门禁拒绝；独立质量总分再高也不补偿。阶段审核是编辑判断，不是学生理解实验或认证服务。

## 实际入口

`configs/visual-first-workflow-v3.json`增加跨题目的创作引导和优化声明。项目plan明确`revision_mode=fresh|revision`；`revision`须给出`revision_contract`与`revision_review`路径。

`review/content_regression.py`验证任务清单、基线媒体哈希及逐项比较。`understanding_render`接受v3并归档合同/校验器；`understanding_film.bindings`绑定合同、实际基线和当前版本。`require_review`在正式稿安装及发布时真正调用`require_regression`，还要求静音首看与基线比较使用不同Reviewer上下文。交付收据保存比较报告的路径和哈希，后续声音阶段重新验证，不能只有提示词而绕过发布检查。

这条真实链路目前接入**监督式改片入口**。既有Sol自主入口仍是从零制作的协议，没有独立的基线比较动作；不能仅换profile就声称已经自动接通。未来模型适配必须携带同一语义合同与实际比较证据，不能把本次监督样片当作国产模型能力成绩。

示例：

```json
{
  "workflow_profile": "configs/visual-first-workflow-v3.json",
  "revision_mode": "revision",
  "revision_contract": "runtime/projects/PROJECT/revision-contract.json",
  "revision_review": "runtime/sessions/SESSION/review-regression-v001.json"
}
```

合同为schema 1，`assets`记录本任务基线的路径、SHA256和时长，`units`记录教学功能、基线实际区间及各项`features`（`state`或`process`）。每项特征由项目决定，不在通用代码中硬编码平抛、五组公式或任何固定条数。

比较报告：`stage=content_regression`、独立Reviewer身份、当前`bindings`、明确pass/revise和授权、阻断项，以及完整`units/features`。每项保留/等价结论含`evidence:[{time,finding}]`；`process`还需时间递增的`phase=before|during|after`。这些字段只能确保审核证据完整、可追溯，不能自动证明描述与像素相符，仍依赖真正独立的看图判断。

绑定字段集合由真实入口生成，不能在人工提示中写死某个字段数量，更不能为凑数编造哈希。静音、文字和音频阶段的绑定本就可能不同；协议描述有误时应核对实现并记录更正，不据此修改内容判断或降低质量标准。

## 状态与失效

| 状态 | 写入者 / 消费者 | 生命周期与失效 |
| --- | --- | --- |
| v3通用profile | 维护者 / 创作者、审核者、入口 | 长期版本，不含某片固定分镜；变更需新匹配证据 |
| `runtime/projects/<id>/revision-contract.json` | 协调者依据任务 / 作者、比较审核、发布器 | 制作前选定的长期基线清单；媒体、功能或授权变化须另立版本，不事后降低要求 |
| `runtime/sessions/<id>/review-regression-v*.json` | 独立比较Reviewer / 正式稿及发布门禁 | 单轮审核，合同/基线/当前媒体/代码变化失效；不由作者写通过 |
| `outputs/<id>/v*/source`与交付收据 | 渲染/发布器 / Reviewer、用户、声音阶段 | 版本化媒体及来源；收据固定比较原答哈希，修改比较需重审交付 |

首次定向回归包含：新版100分仍不能掩盖内容丢失、漏掉某组/细节、变量过程仅给终态、基线被替换、报告陈旧、作者冒充审核、功能等价保留等。不同题材的结构化测试仅验证合同通用性，不代表已制作多学科视频或证明量产稳定。
