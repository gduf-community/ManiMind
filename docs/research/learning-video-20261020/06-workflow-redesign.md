# 工作流改造 从限制创作转为验证成品

状态：研究后的实施建议，尚未修改运行时。

## 改造目标

允许作者模型决定如何讲、如何画、如何分段和如何迭代。系统提供工具、参考和事实依据，独立审核判断实际作品是否达到教学与交付目标。

这不是把提示词中的“必须”替换成“建议”就能完成。当前限制分布于提示词、数据模型、组件能力、时间轴、渲染器和审核器，任何一处仍拒绝有效表达，创作空间就没有真正打开。

也不能因为模型进步而假定它不再犯错。新的生产自由是否有效，应通过新的作品与学习证据判断，而非模型名称判断。

## 三类规则

| 类别 | 处理方向 | 例子 |
|---|---|---|
| 创作方法 | 改为可选引导，不因不采用而拒绝 | 镜头数、时长、布局、颜色、开场形式、是否缩放或提问 |
| 成品结果 | 放在独立审核中，以实际证据判定 | 错误公式、讲解跳步、音画矛盾、不可读、声音截断 |
| 执行与交付边界 | 保留最小必要契约，不能伪装成审美要求 | 密钥保护、资源预算、输出归属、可追溯版本、审核批准 |

“自由创作”不等于任意访问宿主机、无限消耗 API 或删除历史。数据解析和执行接口仍需明确，但不应继续把它们扩张为统一教学语法。

## 当前限制审计

以下位置是当前工作区实查，不表示本轮已经修改。历史隔离实验的原协议、失败和得分继续保留。

| 当前限制或代理标准 | 位置 | 新路径应如何处理 | 最终检查什么 |
|---|---|---|---|
| 黑底蓝黄配色、固定字号与位置、每帧 2–3 个核心元素 | `llm/templates/style_guide.py`，由 `agents/manim_worker.py` 注入 | 改为可选风格示例，不作为全局视觉要求 | 主次、可读性、语义一致与主题适合度 |
| 每个镜头单独 Scene、每步公式调用 `self.wait()` | `llm/templates/manim_worker.py` 及 worker 提示 | 允许连续场景和其他节奏表达，不指定源码写法 | 连贯性、实际观察时间与可维护的执行入口 |
| 规划阶段镜头估时不得少于五秒 | `agents/planner.py`、`llm/templates/planner.py` | 改为可选估时建议；不拒绝有效短镜头 | 实际理解时间，而非估时字段达标 |
| 固定六镜头、每镜十八秒 | `configs/isolated-comparison-prompt.txt` | 不继承为通用规则；由学习目标与实际语音决定结构 | 节奏和解释是否完整，是否符合用户交付要求 |
| 每镜旁白 35–65 字、固定起止留白 | 同上及 `experiments/isolated_media.py` | 不按字数截断论证；提供语音测时、事件对齐工具 | 实际口播有无截断、抢跑、拖空或错配 |
| 图区加侧栏固定布局 | `components/renderer.py` 的 `SIDEBAR`、`_row_layout`、`_build_shot` | 作为可选预设；支持自由布局或直接使用渲染后端 | 指代是否清楚、是否遮挡、关键内容是否足够大 |
| 所有对象从开头一直存在，无显隐与缩放 | 冻结提示词和当前组件能力 | 增加可选事件、对象生命周期和镜头能力 | 变化能否被跟踪，是否造成错误含义 |
| 每镜统一末尾保持 15% | `components/plan.py` | 改为节奏建议；可在任意关键事件停留 | 重要状态是否可感知 |
| 镜头、参数、关键帧和说明行数量上限 | `components/plan.py` | 不作为教学配额；真实资源上限显式配置 | 复杂度是否超过观众或执行环境承受能力 |
| 所有坐标轴必须包含零，限定刻度间隔数 | `components/plan.py` | 改为依任务选择视窗与标注 | 局部视图和尺度变化有没有误导 |
| 全曲线全过程不得超出视窗 | `components/plan.py`、冻结提示词 | 支持有语义的裁剪和局部视图，不强迫把主体缩小 | 必要信息是否被误裁、边界是否解释清楚 |
| 公式只能绑定曲线，不能独立推导 | `components/plan.py`、`renderer.py` | 增加通用数学排版与推导能力；不强制每个公式都有图 | 符号、变换、条件及其含义是否正确 |
| 受限表达式树成为唯一表达方式 | `components/expressions.py` | 保留为可选安全数据工具，不作为所有作者唯一入口 | 任意代码执行隔离、实际数学输出、证据完整性 |
| 代码最少行数、最少动画调用、颜色关键词计数 | `review/manim_code_quality.py` | 去掉教学阻塞效力，可保留诊断信息 | 实际表达效果，而不是源码拼写 |
| 一定要有足够像素运动 | `review/motion_quality.py` | 改为异常提示，结合预期内容判断 | 是否发生播放故障，或关键变化没有被显示 |
| 全图亮度、对比、边缘密度推断精良 | `review/frame_quality.py` | 解码故障仍阻塞；统计量只帮助定位待审区间 | 实际必要文字与图形可读性 |
| 公式一律需要图形 companion、变量颜色冲突自动阻塞 | `agents/reviewer.py` 及对应检测器 | 区分真实误导与合法纯推导、跨语境换色 | 当前语境中符号含义与指代是否清楚 |
| 自动检测任一 block 强制覆盖 reviewer 结论 | `agents/reviewer.py`、`llm/templates/reviewer.py` | 将技术失败与启发式告警分型，后者不能自动充当教学否决 | 不可执行或证据失效仍阻塞，语义告警由证据判定 |
| 只能接收一次原始机器错误反馈 | 冻结隔离实验 | 历史保持；新协议允许同条件的内容审核反馈与有预算迭代 | 修复后重新审片，原始失败和费用不消失 |

统一数据契约是可选制作方式，不是应被删除的所有能力。低成本的数值图、批量练习或对照实验仍可选择它，但自由作者应能采用其他合法路径。

后端 API 的存在性是技术事实，不能因为去限制就假设错误调用可以运行。但“第一行必须这样导入”“必须用某个对象类”应改成该后端的参考与诊断，允许合法的别名、封装和替代实现。逐帧重建公式等高成本做法宜提供性能提示，由真实资源预算与渲染表现决定是否阻塞。

样式文件中还有按固定配色与布局打分的 `REVIEW_CHECKLIST`；本轮未检出运行时调用，不能把它说成当前已执行的审核关卡。后续迁移仍应清理这类遗留提示，防止它们被重新启用。

## 建议的作者输入

任务输入可保持很短：

> 为指定受众制作一部能解释指定问题的视频。这里是受众已有知识、必要事实与来源、交付场景和资源预算。你可以自由选择叙事、例子、媒介、布局、镜头和时长安排。可查询教学与视听参考，也可使用组件或自己编写场景。请根据实际渲染与反馈迭代；不要把表面流畅当成解释完成。

五份研究应按需检索，而非全部常驻上下文。示例要注明是参考，不是输出模板，也不必每次都放入同一道题的完整示范答案。

格式需要服务制作：一段脚本、代码场景或分镜都可以是作者工作材料。最外层仍需要让执行器知道入口、依赖、输出和版本；不能把创作自由误写成系统不用知道运行什么。

## 创作与审核的分工

建议的新路径是：

```text
任务与事实
  -> 作者自主探索、写作、选择工具
  -> 渲染可审阅的真实音画草稿
  -> 独立审核：指出问题与证据，不指定唯一修法
  -> 作者自行修订，保留版本与成本
  -> 新版本重新审核
  -> 批准后正式发布
```

作者不必经历固定数量的规划阶段或调用固定数量的 Agent。任务可并行时使用已有 worker；同一个作者也可以维护连续的解释思路。独立 reviewer 仍然与生产者分离，作者自检不替代发布审核。

必须在真实音画上完成审核。若缺少音频、只能看抽帧或存在无法覆盖的关键区间，报告应明确标注证据不足，不能静默给出“完整审片通过”。

现行文档将后处理整体放在审核之后。新路径需要显式区分“为审片生成音画草稿”和“发布已批准成片”，实施时同步修订架构文档与门禁，不通过重命名绕过现有规则。本轮不执行这一变更。

## 审核标准不再规定制作方法

建议使用少量结果维度，并允许按课程任务判为不适用：

| 维度 | 审核问题 | 有用的证据 |
|---|---|---|
| 正确与诚实 | 事实、条件、推导、模拟性质和范围是否准确？ | 来源、公式复核、实际关键画面与口播 |
| 解释完整 | 核心结论凭什么成立？受众是否需要未交代的前提？ | 具体推理链与断点 |
| 表示可理解 | 对象、变量、参照、变化与音画指代是否清楚？ | 变化前后及过程区间 |
| 视听可达 | 必要内容在目标环境里能看清、听清吗？ | 编码后媒体、实际声音、设备检查 |
| 参与与质感 | 是否有值得跟进的问题？表达是否自然、有主次？ | 具体片段与目标受众反馈 |

数学错误、关键音画矛盾、核心解释缺失、必要信息不可读等可以构成阻塞。风格偏好和可进一步精修的细节列为建议，不混在同一“必须整改”列表中。缺乏证据与发现错误也应分别记录。

推荐反馈形式是“问题、时间区间、证据、对理解的影响、严重程度”。例如：

```text
问题：口播说恰好相切时，实际画面仍有两个交点。
证据：该句对应的音频区间、同区间视频与参数状态。
影响：观众无法把判别式为零与一个不同实根建立对应。
判定：阻塞。
修复方式：由作者选择，不限定增加哪个组件或镜头。
```

不再让高视觉得分抵消错误推导。质量概况可以分维度报告，但 AI 给出的 80 分不应表述为学生理解率 80%。

## 组件怎样帮助自由创作

优先提供可组合的小能力，而不是更多“全套课程模板”：

- 文字、公式与数字的可靠排版，以及可替换的风格预设。
- 图形、坐标、数据对象与实际数值的对应工具。
- 对象出现、退出、强调、标注、轨迹和局部观察。
- 公式步骤、对照布局、关键状态快照。
- 实际 TTS 测时、语音事件锚点、字幕与最终媒体证据。

组件默认样式应能覆盖、组合或不使用。不把主图加侧栏、三段单调变化、统一停顿等场景设计藏在“通用组件”内部。

ManimGL、HTML 等后端继续复用现有接入，不复制第三方底层实现。工程层负责稳定执行和可观测性，作者负责本题的解释设计。

针对 [火柴人与数学、物理的案例研究](07-animation-vs-knowledge.md)，还可按需求提供角色或探测器表演、对象接触、跨场景身份连续性和事件声音等可选能力。其作用是让知识参与行动，不是要求每片加入主角或采用闯关结构。科学状态的时间与表演节奏应能区分：可以设计注视、准备和反应，不能用通用缓动悄悄改变正在讲解的匀速或加速规律。审核检查实际语义，不检查作者是否使用了这套表现方法。

开放代码路径之前，需要验证执行隔离与资源边界。当前项目文档已经说明旧代码实验不是可无人值守运行的沙箱；不能把“解除表达式限制”实现为让模型在含密钥的宿主进程任意执行。

## 状态与版本

不增加混杂的全局记忆。未来实现继续使用现有目录职责，以下是拟议归属，不是本轮新增运行状态：

| 材料 | 写入者与消费者 | 生命周期和失效条件 |
|---|---|---|
| 受众、任务、必要事实、版本化参考 | coordinator 整理，作者与 reviewer 消费 | 长期项目；事实或目标变化后关联作品重新评估 |
| 草案、尝试、反馈和修复日志 | 作者或 reviewer 写各自记录，编排器消费 | 单轮 session；新版本不抹除旧尝试 |
| 代码、音轨、视频、测量与清单 | 对应工具写，作者和 reviewer 消费 | `outputs/<project_id>/` 按版本保留，可回放 |
| 独立批准 | reviewer 写，发布器消费 | 绑定所审内容；影响内容、媒体或执行规则的变化使批准失效 |

参考指南不是批准凭证。机器检查通过也不是批准凭证。长期事实与短期修复过程仍不混写。

## 怎样验证新路径有效

先区分两个问题：

1. 同一模型使用新旧路径，作品是否变好？这是工作流效果。
2. 不同模型使用同一条新路径，差距有多大？这是模型效果。

两者最好形成交叉对照。每个题目共享受众、必要事实、交付场景、配音条件和预算口径；允许不同工作流使用其真实创作能力。作者上下文隔离，主 Agent 不给其中一个候选单独补教案或修场景。研究资料对各候选一致可见。

如果要复用已经产出的旧视频，只能作为历史参照；不能冒充与新视频同时随机生成的严格实验。新旧工作流的公平对照需重新冻结协议，保留每次失败和修复。

选择多个有区别的题型，例如极限过程、代数结构、物理机制。每个组合需要重复样本，样本数按成本计划确定并如实报告。一次好片说明可达到，不说明可稳定量产。

学生验证先做小规模质性观察，例如邀请 6–10 名符合受众条件的人定位理解断点；这不是足以证明普遍增益的样本。正式比较需按预设效应和统计设计决定样本量，采用可比前后测、新例迁移题和必要的延迟测量。

成本口径包括作者、审核与失败修复调用，TTS、渲染资源和人工时间。分别报告单次尝试成本与每部合格成片成本，不把拒绝样本的费用删掉，也不把订阅额度当作无成本无限资源。

## 实施顺序

1. 建立独立的新创作协议，保留冻结实验与原始失败；同步架构规范。
2. 去掉创作配额和代理指标的阻塞作用，保留必要执行边界与独立发布审核。
3. 提供真正可用的自由场景入口、灵活时间轴与可选组件，而非只放宽提示词。
4. 验证多种有效风格不会被误拒绝：静态推导、连续长镜头、无侧栏、局部放大、独立公式。
5. 验证真实错误仍会被挡住：错误等式、音画错配、必要信息不可读、未审核发布。
6. 再运行同条件模型比较和学习验证，更新质量与成本结论。

实现阶段需要把这些建议转成有测试的代码。本轮仅交付研究，未修改以上模块或门禁。
