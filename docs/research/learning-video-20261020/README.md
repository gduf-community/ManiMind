# 知识视频教学与视听研究

日期：2026-10-20。面向 ManiMind 的高中、大学知识演示视频。

## 核心判断

接下来的优化目标应从“让模型稳定填出合法镜头”转为“让作者充分解释，让审核验证解释是否成立”。创作自由不是质量保证，但当前一些限制确实排除了有效的教学表达。需要放开的是创作方法，不能放弃的是对成品的判断。

这组研究不把 3Blue1Brown 的外观当模板，也不把研究结论变成新的镜头配额。主要结论是：

1. **讲解的单位应是观众理解上的推进，不是固定秒数的镜头。** 一个概念可以需要连续长镜头，也可以需要几个短对照。
2. **动画的价值在于显现关系。** 观众应能辨认谁在变化、什么没变、变化产生什么结果。屏幕有运动不等于观众理解了变化。
3. **兴趣最好来自一个值得解决的知识问题。** 提问、反直觉、实际用途都可以采用，但不能以吊胃口代替解释。
4. **底层逻辑要给出可使用的理由。** 不只展示结论，还让观众有能力解释一个新例子，并知道结论在哪些条件下失效。
5. **精致度来自画面、语言、声音共同服务同一个意思。** 大面积留白、细线、深色背景、复杂转场，本身都不是高级感。
6. **审核也需要去除错误代理指标。** 代码行数、动画次数、颜色数量、像素变化量不能充当教学质量的硬门槛。

这些是本项目的综合判断，不是论文证明了某一套自动工作流必然有效。研究依据、适用条件和项目推论在各专题中分开呈现。

## 与已有视频的关系

当前对照的固定六镜头、每镜十八秒、旁白字数、固定侧栏、禁止显隐和缩放等限制可以在 [冻结提示词](../../../configs/isolated-comparison-prompt.txt) 中核对。组件本身也有布局和表达能力限制，不能只删提示词就声称作者自由了。

主工作流也有同类问题：[样式提示词](../../../src/manimind/llm/templates/style_guide.py) 被 Manim Worker 注入，规定配色、文字位置、字号与每帧元素数量。因此改造范围不能只覆盖这一次对照实验。

另一个问题位于原工作流的审核代码：[代码质量检测](../../../src/manimind/review/manim_code_quality.py) 把最少行数、动画调用数、颜色信号等列为阻塞原因；[运动检测](../../../src/manimind/review/motion_quality.py) 使用跨帧亮度变化和变化像素比例。这些测量可以帮助发现异常，但无法独立证明“解释得好”。

最初的速度试片提供了另一种工程实例：[试片说明](../../velocity-pilot.md) 和 [场景源码](../../../examples/instantaneous_velocity.py) 包含逐句时间安排、量与图的对应、推导、局部放大等自由表达。它不是无干预量产能力的证据，也不是每个新选题都必须照搬的分镜。

因此，旧片与新片的差别不能全部归因于模型。题目、教案、工具、创作权限、迭代机会和配音也不同。旧实验继续保留；新的工作流效果应另开实验验证。

## 研究怎样用于创作

建议给作者的是一个简短创作任务和可查询的参考资料，而不是每次把全部研究塞进提示词。可以向作者提出以下问题，允许采用自己的表达形式：

> 这部片子准备让哪类观众明白什么？最容易卡住的地方在哪里？什么例子、图像或推理能帮助他们跨过去？看完后，他们能解释哪一个以前解释不了的问题？

镜头数量、时长、版式、媒介、讲解顺序和是否使用提问，由作者按题目决定。复杂公式、对照、静止画面、连续长镜头、代码生成动画都可以使用。用户指定的交付格式、预算和受众仍是任务条件，不是可以擅自忽略的限制。

## 建议保留的审核底线

审核关注结果，而不是是否使用某一种方法：

- 事实、公式、适用条件和实际画面没有实质性矛盾。
- 核心结论有适合目标受众的解释，不能只有宣告或跳步。
- 音画指向一致，重要状态和推理步骤能够被感知。
- 必要文字、图形、声音在目标观看环境中可辨认。
- 证据不足时标注未验证；AI 审片不能冒充学生学习效果验证。

高级感、兴趣、节奏的不足也要记录，但不能用漂亮画面抵消事实错误，或用“有三种颜色”抵消逻辑缺失。

## 实施状态

本轮完成研究文档和改造建议，**尚未改变运行时代码、冻结实验或审核放行逻辑**，也未产生新的候选模型视频。

下一轮实现应先建立自由创作路径并更新对应架构文档，再用同一学习目标比较旧路径与新路径。验收重点不是“放松后还能渲染”，而是是否减少解释断点、是否真正允许不同的有效表达，以及是否能通过独立成片审核。具体顺序见第六份文档。
