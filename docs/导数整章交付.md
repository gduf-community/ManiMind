# 导数整章交付

`postproduce/chapter_package.py` 是有界监督打包入口，不是媒体审核者、制作调度器或自动批准器。沿用新的 `unit-v001.json` 中八个项目的固定顺序，保留第一课旧单元及 `captioned-v007` 原来源。新增七课尚未齐时不能 prepare；一条视频、候选、八个文件名或库存 status 都不代表整章。

最初实现阶段只验证 mock 协议；这不能证明真实媒体通过。后续实际 `package-v004` 已完成八课有声字幕、独立章节组装审核、独立最终合辑审核和新桌面目录发布，具体来源与实际收据见[制作记录](导数整章制作记录-20261102.md)。`package-v002` 的25fps合并失败、`package-v003` 的最终媒体范围漏项拒绝均保留，未覆盖或改判。当前实际生产使用[整章合并时钟适配器](整章合并时钟.md)的新 contract；下方保留原冻结入口的协议说明，不能直接重放旧入口来复用新版审批。候选不等于交付，完成判断仍依赖当前实际manifest和release-complete。没有复用或伪造 `playback_package` 的旧 hashes 批准，也没有绕过 isolated montage 的 comparison scope。当前交付仍是未人工听审、未学生测试的完整预览。

## 输入与调用

在仓库根目录调用 `python -m manimind.postproduce.chapter_package`。接口仅为 `prepare(request)`、`bindings(plan)`、`assemble(plan, assembly_review)`、`release(plan, media_review, desktop)`，CLI 对应：

```bash
python -m manimind.postproduce.chapter_package prepare --request /absolute/path/request.json
python -m manimind.postproduce.chapter_package bindings --plan /absolute/path/plan.json
python -m manimind.postproduce.chapter_package assemble --plan /absolute/path/plan.json --review /absolute/path/chapter-assembly-review.json
python -m manimind.postproduce.chapter_package release --plan /absolute/path/plan.json --review /absolute/path/chapter-media-review.json --desktop /Users/pengweitai/Desktop/导数整章-新版本
```

request 是 JSON，必须由主控显式给出，不自动发现最新版本：

| 字段 | 契约 |
| --- | --- |
| `chapter_id` | `math-derivative-chapter-20261102`，必须等于 unit_id |
| `version` | 新的安全版本标识，如 `package-v001`；失败后也不能复用 |
| `unit` | `runtime/projects/math-derivative-chapter-20261102/unit-v001.json` |
| `deliveries` | 严格有序的八个 `unit_film.release_captioned` 的 `delivery.json` 路径，不能是 candidate.json 或目录 |
| `science` | 同顺序八个已绑定到各课实际 render inputs 的公共数学/教研 JSON 路径；第一课可用旧 `course-context-plan.json`，02-08可用各课 `scientific-brief-v001.json` |
| `shared_science` | 可选显式列表，建议包含已冻结 `chapter-brief-v002.json`；仅提供范围，不授予通过 |
| `actors` | 六个字段：`author_agent/context`、`main_agent/context`、`adapter_agent/context`，每个均为实际规范 UUID，不用角色名替代身份 |
| `session_id` | 默认 `math-derivative-chapter-20261102-package-author`；执行该包时不与逐课制作 session 混写 |

八课项目顺序固定由传入 unit 验证：

3. `math-derivative-ch03-rules-20261102`
4. `math-derivative-ch04-chain-20261102`
5. `math-derivative-ch05-monotonicity-20261102`
6. `math-derivative-ch06-extrema-20261102`

02-08 的真实 captioned 版本由主控填完整路径，不预设 v001 已发布。`CODEX_THREAD_ID` 必须等于实际调用 adapter 的 agent UUID；上下文和其他参与者 UUID 由主控据真实聊天提供，程序不生成身份。UUID 形状校验和环境匹配不是外部身份认证，独立性仍依赖真实分工，不能把另起随机 UUID 当成独立审查。

## 三阶段门禁

### Prepare

先验证课程 catalogue/unit 结构和八课数量，再从每课当前 `caption_bindings` 经 candidate → alignment → silent delivery → render plan → `curriculum.verify_context` 获取真实 project ID 与原单元。检查顺序、重复路径、重复媒体 SHA、原 source delivery SHA、caption review SHA、当前 candidate bindings、原片 bytes、源码及实际 examples 依赖。01 必须匹配 unit 中 `existing_first_lesson` 的显式路径、原单元及视频 SHA；02-08 必须实际绑定新的章 unit。

复用 `lesson_opening._body` 的原生字幕来源复核及 `unit_film.verify_delivery`，并逐课调用公开 `unit_film.release_captioned`，将重新审核验证后的字节复制进本版本 `outputs/<chapter>/chapter-packages/<version>/verified-lessons/`。不重烧字幕，不覆盖旧发布，不将旧课批准转移给其他课。plan 中的 `coverage` 是八课来源完整性检查，不是媒体覆盖审批。

长期 `plan.json` 绑定 unit、所有原 delivery/review、当前 caption bindings、源码、公共范围和验证副本；session 的 `chapter-assembly-input.json` 提供八课媒体路径、课纲/出口/handoff、catalogue 摘录、逐课 science 与公共章范围，供新的独立 reviewer 看实际媒体核对，不把 scene 源码当成媒体已实现的证据。prepare 不写 pass。

### Assemble Candidate

先消费真实 `chapter_assembly` pass，然后才排他创建 candidate 目录，运行原生公共 FFmpeg `pilot.run/probe`。滤镜只有逐段 video/audio PTS 归零、48k mono 音频格式转换及八输入 concat；完整顺序拼接，不裁切、缩放、变速或加字幕。要求每个源本来就是 1920×1080、30fps、h264/yuv420p；输出 libx264/yuv420p、AAC 48k 单声道，不用强制缩放掩盖输入错误。编码及全量解码 timeout 为 1800 秒。

校验单课及全片帧数、音视频起点/时长、编码与音频格式，全量解码必须成功。生成 `candidate/chapter-candidate.mp4`、`candidate.json` 和 session 的七个边界前后一帧，共14张实际取帧，以及 `chapter-media-input.json`。packet 绑定实际整章视频 SHA、segments、累计边界、probe、执行命令、assembly review SHA 和全部来源。候选永远不是发布。

### Release

必须消费新的 `chapter_media` pass，reviewer context 不能与 assembly reviewer 相同，也不能是任何 author/main/adapter 或原制作人。重新核对源绑定、候选 SHA、时长/帧数/全量解码及边界像素，再复制到一个**不存在的 Desktop 直属子目录**。禁止默认 iCloud/GitHub 路径，不触碰已有首课 Desktop 文件夹。

包内含 `chapter.mp4`、八个分课目录及原字节 `lesson.mp4`、带标题/时长的 `目录.md`、逐课 provenance（讲稿、scene 和真实已声明 examples 依赖、实际 render inputs、字幕资产、来源与审核及审核帧）、chapter-provenance（unit、公共范围、章 plan/candidate/两次审核/边界帧）。`manifest.json` 最后写入，含全体交付文件 SHA 及完整源绑定。复制后再核对来源和媒体审核，任何漂移不写完成 manifest。无 manifest/`release-complete.json` 的残留目录只能当 pending 现场。

## 独立审核协议

不提供生成 pass 的函数。由真实独立 reviewer 在 `runtime/sessions/` 写报告；adapter/main/作者不得代填。报告使用已有 `unit_film._review` 的 generic stage 基础字段，并增加整章 checks：

- `stage` 必须精确为 `chapter_assembly` 或 `chapter_media`；`bindings` 必须逐字结构等于相应 input packet 中 bindings，不消费旧 hashes 协议
- `status: pass`、`reviewer_role: independent`、真实 UUID `reviewer_agent/context`、`release_authorized: true`、`blocking_findings: []`
- `listening_reviewed: false`、`listening_status: not_performed`、`student_tested: false`，不得夹带 naturalness/pronunciation/ASR 已认证声明
- 有序 `lessons` 恰好八行，各行精确绑定 `project_id`、`source_delivery: {path, sha256}`、`science: {path, sha256}`
- assembly 各行 `checks` 必须有 `coverage`、`handoff`、`source_completeness`；media 各行必须有 `full_lesson`、`captions`、`av_continuity`
- 每项 check 必须 `status: pass`、非空 `conditions` 字符串列表和非空 `evidence` 列表；明确适用域、单位、前后课出口等实际条件，不以“代码有实现”或单一总分替代观察
- 每条 evidence 含 `path`、`sha256`、`video_sha256`、范围内的数值 `time` 和非空 `finding`；frame 必须是真实 PNG/JPEG，复用原像素比对验证与媒体对应时刻一致。assembly 引用该课 verified video，media 引用整章候选且 time 落在该课实际 segment 内
- media 另有恰好七行 `boundaries`，每行 `before/after` 精确复制相应实际取帧收据，`checks.seam` 的 evidence 必须分别对这两帧给出观察和适用条件
- 原逐课 reviewer context 不可重新标签为章节审核；media 与 assembly 必须不同 context。身份/绑定/逐课证据缺一项都拒绝

教研范围是 reviewer 的核对基线，不代表教材官方认证；工程解码/复制成功也不代表实际听审或学生学会。这里只交明确标记待听审的完整章节预览。若需听审认证，另建显式协议，不把本字段改成 true 绕过当前合同。

## 状态归属

| 状态/目录 | Writer | Consumers | 生命周期与失效 |
| --- | --- | --- | --- |
| 原 unit/science/context | 原教研编辑/各课制作人 | prepare/独立章 reviewer | 长期原始版本；本模块只读，内容变化重做包与受影响批准 |
| `runtime/projects/<chapter>/chapter-packages/<version>/plan.json` | adapter | 两阶段 reviewer/assemble/release | 长期不可变章来源事实；任意源/实现/复制副本漂移即失效 |
| session `prepare-pending/complete`、`release-pending/complete` | adapter/publisher | 操作者 | 单次动作收据，pending 保留，只有相应 complete 才表示动作完成；孤儿/未知结果人工诊断，不自动重放 |
| session assembly/media inputs、审核、boundary PNG | adapter/实际独立 reviewer/assembler | 下一阶段 gate/审计者 | 单包短期协作证据；当前媒体、范围、报告、像素或代码变化即失效，不进入长期学习者画像 |
| outputs `verified-lessons` | 公开 unit_film publisher | chapter reviewer/assembler/publisher | 当前包 create-only 原片副本；bytes/来源变化失效，不覆盖旧课 |
| outputs `candidate/pending.json`、MP4、`candidate.json` | assembler | 媒体 reviewer/publisher/操作者 | 单次组装尝试；未知/失败保留 pending 和已写文件，无 candidate.json 不能发布，禁止原版本自动重试 |
| Desktop 新文件夹/manifest | publisher | 用户/审计者 | 成功复制后的版本交付，manifest 最后写；源/批准漂移拒绝完成。只复制，不上传或写 Git |

所有新增记录含 writer、consumers、lifecycle、invalidation。长期只写章 plan；临时阶段包、审核和取帧只在指定 session；媒体只在该包 outputs。目录 `mkdir(exist_ok=False)` 和 JSON `open('x')` 提供同版本排他领取，不合并、不续写、不清锁。重放即拒绝；修复或人工诊断后用新的 package version/session 版本，旧现场保留。不要自动重试已超时或外部结果未知的动作。

静态 examples import 检查要求真实本地依赖存在于原 render input_hashes，逐一核对哈希后一起复制。动态导入不靠扫描猜测；相对 examples import 当前显式拒绝，需要扩展支持才准入。未声明依赖应先回制作层形成新合法来源，不在打包时补造旧收据。

## 验证边界

整章试作补充了[数学讲稿口述引导](数学讲稿口述引导.md)：明确分子、分母、平方对象和完整因子，按连续意群表达，不把逐字朗读括号变成统一模板。已有课程工作流文档被实际渲染绑定，本轮不改写这些冻结输入；新引导供后续制作显式选用，不能据此声称旧自主模型入口已经自动接通。

`tests/test_chapter_package.py` 独立构造八课协议 fixture，mock 原逐课媒体 gate 与 FFmpeg/像素，不修改或复用其他测试的 fixture。覆盖缺课、顺序/重复/真实 context 错配、候选冒充来源、原 delivery/review/science/examples/实现/副本漂移、自审和旧批准复用、全八课条件/证据、完整 concat 参数、独立媒体批准、七边界、候选篡改、失败 pending、已有 Desktop 不覆盖及复制中审批漂移。测试通过只说明协议拒绝/复制逻辑，不声称真实媒体解码、音画连续、听审、学生理解或整章已交付。
