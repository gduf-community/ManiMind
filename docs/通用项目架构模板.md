# ManiMind 架构概览

ManiMind 把课程制作分成计划、动画、独立审核、声音字幕和交付。项目目录保存长期事实，每次协作保留自己的操作与审核记录，每个候选版本留下真实媒体和来源。

## 一课怎样流转

```text
课程目录与备课
    -> 动画计划与场景
    -> 实际渲染与独立审核
    -> 口语讲稿与完整意群配音
    -> 声画、字幕审核
    -> 分课播放包与整章汇总
```

课程、动画和制作工具可以各自改进。视觉变化影响对应画面及下游审核；仅讲稿变化时，由相关阶段重新检查。

## 目录分工

人类入口由 `README.md`、`作品/` 和 `docs/` 组成；执行规则、技术契约及精确审核数据在 `ai/`。历史设计与实验归入 `archive/legacy/`，本机私密历史进入 Git 忽略的 `archive/local/`。

核心编排代码在 `src/manimind/`。课程事实与计划保存在 `runtime/projects/`；单次协作在 `runtime/sessions/`；版本媒体在 `outputs/`。作品索引给观看者显示清楚名称，制作证据继续使用原生路径。

## 当前工程边界

课程生产采用监督式制作链：v4.3.1 绘图配置、v3 公式连续性取证与独立回归，再沿原音和单套字幕链交付。旧模型实验和基础 CLI 保留在历史实验范围。

实现、角色和状态生命周期的详解已移到 [AI 执行架构](../ai/architecture/执行架构详解.md)。[架构白板](architecture.canvas)同时显示制作链与新的阅读/归档分区。
