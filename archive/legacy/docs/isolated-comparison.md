# 隔离的整课组件对照

## 实验范围

对照当前会话配置的 GPT-6 Astra、新版 DeepSeek-V4.1-Flash-1017，以及国产旗舰候选 Kimi K3。Kimi 的选择不宣称它在所有榜单或全部任务上排名第一。所有作者只接收同一个课程目标、数学事实包、组件协议和评审规则；不提供旧成片、示例教案、聊天历史或他人输出。

选题为一元二次函数判别式与实根数量，六镜头各18秒。镜头内容、顺序、参数、字幕、完整旁白由候选自行生成。共三次独立重复，每次最多两次请求；修复输入只有原任务、自己的上一答和逐字机器错误，不含主Agent建议。主片固定取第一次重复中最早通过机器检查的版本，不按质量挑片。另两次只测协议/逐帧数学预检重复性，未经渲染审片不计为视频成功。

组件、版式、字体、线条和TTS是共用工程基础，不归功于任何候选。此实验测量既定组件内的规划/表达/参数能力，不等同于自由生成任意视频的能力上限。

## 隔离与冻结

`experiments/isolated_comparison.py init` 在首次生成前冻结配置、完整提示和组件源码哈希。API请求只含同一system/user文本，不启用工具，不复用对话。Codex使用全新临时CODEX_HOME和空工作目录，仅临时使用现有认证；禁用记忆、项目文档、skills提示、插件、shell、浏览器、子Agent等，替换默认任务指令为公共system文本。临时认证不进入仓库或输出，进程结束即清理。任何实际工具活动使样本失效。

不同服务的隐藏系统政策、分词器和推理实现无法完全一致，不能宣称底层输入逐字等价。统一采用各自high推理档，但high不是相同算力保证。公共输入字节哈希一致；接口参数和响应模型另行记录。DeepSeek滚动别名不冒充不可变版本证明。

共享时限600秒、最终答案50000字符上限。国产API最大输出32768 tokens（包含思考计量）；Codex CLI没有对应硬上限，因此只能披露不对称性并记录实耗，不能伪称严格等token预算。所有请求在执行前登记，原始响应与失败永久保留，网络错误不自动重试。原始输出不由人手改写；发布ID重映射是固定元数据变换，镜头内容不得改变。

## 工作流与状态

1. 冻结协议，三路独立生成与机器预检。
2. `isolated_media.prepare` 统一Tingting/rate240配音，生成字幕与时间证据；不得加速、截断或改旁白。
3. 既有components pipeline渲染、抽帧、记录实际对象证据。
4. 去除作者名、模型名和成本信息后，独立Reviewer审看每个镜头；同时核对叙事/数学/音画时间。不能伪称已经听过未监听的音频。
5. 组件发布审核和新增媒体审核同时通过后才合成带声单片；最后按预注册顺序制作完整对比片。失败片只作为明确标注的实验样本，不冒充课堂成片。

| 状态 | 写入者 | 消费者 | 生命周期与失效 |
| --- | --- | --- | --- |
| `runtime/projects/<suite>/protocol.json` | coordinator | 所有runner/reviewer | 生成前冻结；提示/配置/实现变化阻断续跑 |
| `runtime/sessions/<suite>-generation/<run>/attempt-N/` | runner | evaluator/reviewer | 单次请求、原回答、用量、错误；不可覆盖，保留失败 |
| `outputs/<suite>/<run>/answer.json`、`selection.json` | deterministic runner | media/reviewer | 从原答解析派生；绑定原记录，禁止语义改写 |
| 同目录 `audio/`、`media-preparation.json` | media worker | reviewer/assembler | 从冻结脚本生成；源/音轨变化使媒体审批失效 |
| 同目录 `media-review.json` | independent reviewer | assembler | 必须独立且绑定原稿/音轨/视频/准备清单；变化即失效 |
| 独立component project的plan/review/render | 既有组件工作流 | reviewer/publisher | 沿用已有冻结、attempt和哈希门槛 |
| `generation-report.json`、对比片及交付清单 | evaluator/assembler | 用户 | 可从证据重建；不写审核授权，不覆盖失败 |

## 成本与结论

逐请求保留原usage，包含失败/修复，缓存与思考按提供方返回字段记账。缺失usage记未知，不记零。DeepSeek报告峰谷价格区间；Kimi单列可能的缓存写入费用；Codex报告标准API等价估算，不能当订阅扣款。生成成本、统一评审成本、共用基础设施开发成本、TTS和渲染墙钟时间必须分开，不用“每次成功调用价格”冒充“每条可交付视频成本”。

报告首轮/修复后机器通过率与实际审片通过率，匿名量表五项总计100分（数学30、解释25、视觉证据20、节奏15、清晰度10）。一题三次的小样本不能证明普遍可靠性，也不能给出跨学科“确定最强”结论。

## 授权的第二阶段

用户明确允许“第二阶段统一加一次自修复”。新增 `isolated_render_repair.py`，不改冻结的第一阶段实现、配置、组件、提示或记录。扩展协议保存到 `runtime/projects/isolated-20261020-render-repair/`，继承的是原始基线配置，不把其中的基线ID伪装成新实验；另存parent协议哈希、扩展实现哈希、授权、单次预算和新匿名项目ID。

只有固定主样本已通过机器预检、且真实原生渲染失败的候选才可使用机会。成功者无需消耗；生成超时者不能用这次授权重抽样，也不能拿第二或第三次重复替代主样本。输入严格等于公共包、自己的原答、原渲染记录的完整 `stderr_tail` 与中性重返JSON指令，不给排版建议。原始stderr可能含原工具进度日志，不作人工摘选。

扩展runner只发一个请求，失败也不重试，另记usage与成本。扩展 `verify` 在准备媒体和最终合成前同时验证父记录、真实报错、原请求、扩展哈希和预算。渲染及独立Reviewer门槛仍全部保留。第二阶段成果与基线分别报告，不追溯修改基线通过率。

授权登记由扩展coordinator原子创建在父实验session的 `render-repair-20261020-once.json`，绑定本次授权与唯一扩展suite；消费者为所有扩展入口，实验期内不可覆盖，不因失败退还额度，不允许串联扩展。初始化即冻结符合条件的失败渲染：原计划须仅作ID映射，启动输入指纹须与现有冻结组件相符，原生wrapper、失败日志和事件文件均绑定哈希；请求前或后续媒体验证发现变化即失效。

## 失败样本的诊断展示

被拒绝的候选不经过 `pipeline.publish` 或 `isolated_media.assemble`，其拒绝结论不改成通过。若需要展示失败，可独立提出 `experimental_diagnostic_edit` 剪辑：完整原始静音画面与原始108秒配音按零点合并，不修内容/节奏，另加全程“未通过交付审核、非课堂成品”警示。不能用普通对比审批替代这个诊断剪辑的独立审批。

coordinator生成 `outputs/<suite>/comparison/plan.json` 和说明素材，Reviewer在匿名评分锁定后审看标记与剪辑方案，在 `runtime/projects/<suite>/comparison-review.json` 另写仅限诊断用途的审批；`isolated_montage.py` 校验计划、素材、原拒绝结论、评分及拼接实现哈希后才处理。原候选分数始终基于未加标记的原始帧。输出永久标为诊断资料，不计入成功成片率；变化使审批失效。这不是放宽原质量标准或增加候选修复次数。
